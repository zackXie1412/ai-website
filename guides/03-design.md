# 修改设计

先读 prd.md、style-card.md（含“本站设计方案”节；旧站没有该节时按需补写）、现有 theme/ 与 [模板规范](../references/template-spec.md)。结构性改动（增删栏目、页面或首页大区块）先更新 prd.md 再改模板；设计方向性变化更新风格卡的本站设计方案节；日常微调直接改 theme，客户认可后记入反馈行。维护性修改不重走 PRD 确认流程。

改完 build 后先自审一轮再交客户：serve 并截图（桌面 1280 + 手机 375），对照所用风格档的自检清单逐项检查（色彩纪律、字重、分区方式、留白节奏、缺内容降级、无横向滚动），发现问题修完再交。客户反馈的视觉取舍记回风格卡。

针对客户反馈改布局、配色、图片呈现或响应式样式，保留内容数据。设计能力可配合其他可用技能；将被客户认可的取舍补回风格卡。

调整幅度较大时可先 `snapshot -m "修改前设计"`，随后改 theme、build、serve。快照只保存 theme/，设计相同不新增；它是本地撤回工具，不是平台设计版本。内容、公司资料、栏目、采用图片和风格卡不随设计快照回滚。

`restore <编号>` 会备份当前 theme，恢复历史设计并保留最新内容。当前栏目可能与旧设计不匹配，补齐模板后再 build。支持 _default 模板，尽量降低恢复时的栏目耦合。快照保留最近十份；不把本地快照历史同步冒充平台历史。

修改栏目名称或路径时更新 columns.json 和必要导航；生成会重新检查页面可达性。新栏目使用默认模板或专属 list/detail，不创建平台自定义字段模型。旧项目 fields 仅作兼容读取，新参数用正文表格。

用户满意后可导出当前静态包。真实发布等平台接入；无需模拟线上站、逐内容刷新或运行旧 publish 命令。
