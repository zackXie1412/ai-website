# 平台接入边界（待实现）

本版实现本地制作，不调用 MCP、不上传、不处理 JWT 或平台会话，也不在文件中存凭证。

职责约定：
- 本地：资料整理、采用内容工作副本、设计、图片处理、静态渲染与检查。
- 平台：身份与站点权限、业务草稿、输入修订、文件接收、托管预览、发布和业务版本。
- 后续传输脚本：按 MCP 分配的受限签名地址上传文件字节；MCP 处理上传登记、完成确认与发布，不传大段 Base64。

未来顺序：保存采用内容 → 获取平台草稿快照 → 本地生成 → 上传清单与文件 → 平台确认 → 预览 → 经授权发布同一不可变包。平台已修改草稿时重新获取并处理差异，不直接覆盖。

当前 manifest.json 的 schema_version=1 是本地导出格式，包含文件路径、字节数、SHA-256、源摘要、设计摘要、package_hash、form_mode 和 platform_ready=false。它不是平台上传协议，也没有虚构的 site_id、draft_revision、package_id。后续接入时由适配层补充平台签发字段；不要把本地 UUID 或摘要当成服务端授权。

导出目录 dist/ 只包含公开文件。设计恢复需要的源归档应单独放私有存储，不能与公开静态文件混放。materials/、facts.md、style-card.md 和完整工作空间不上传；images/、theme/assets/ 是明确的公开资源目录。

正式接入前需替换本地表单演示片段，接入平台四字段版本化契约、预览上下文与统计脚本。保持 __site 路径由平台保留。平台预览与发布使用同一包，不能发布阶段改写 HTML 或重新渲染。

本地默认 Node + Liquid 是当前工作方式；平台最终只依赖静态产物契约。未来若使用其他生成工具，需另行验证同等资源完整性及接入要求，不能声称当前 yz 工具自动兼容。
