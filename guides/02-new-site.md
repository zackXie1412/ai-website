# 本地建站

读取 [工作空间与命令](../references/commands.md) 和 [模板规范](../references/template-spec.md)。以现有资料、目标客户和品牌偏好决定结构，不强制每家企业都有同一组栏目。

1. 在新的空目录运行 `init <目录> --name 公司名 [--locales zh-CN,en] [--style editorial]`。工具创建数据文件、基础模板和 style-card.md；编辑式风格档使用极简编辑式基础模板（视觉规范见 [编辑式设计语言](../references/style-editorial.md)）。基础模板可直接生成，但仍需要 AI 根据客户资料完成设计。
2. 根据资料写 prd.md：目标客户、语言、栏目结构、页面清单及每页区块、各区块的内容来源、资料缺口（缺的注明省略，不编造）。选编辑式时按其图片清单核对图片缺口，缺口决定降级程度。篇幅按站缩放，小站几十行即可，不做成问卷。先出草稿请客户确认结构再动模板，把返工挡在写模板之前；客户已明确授权继续时不逐条追问。
3. 填写公开信息，按需要调整 columns.json；用 `new` 创建内容，填写来源、正文和采用图片。新内容 visible=true，仅表示下次生成显示。产品规格用正文表格，避免新增自定义字段配置。
4. 在 style-card.md 记录品牌颜色、字体、参考偏好、组件倾向，并在“本站设计方案”节确定版式与区块模式、品牌色到 CSS 变量的映射、字体层级、组件清单；写模板前先定这一节，多页才长得像一套。按需调用可用的设计或图像技能；模板通过变量显示企业事实。原始资料留 materials/。
5. 运行 `build`。修复失败项，审阅提醒。在 `serve` 后用浏览器查看实际页面；至少看首页、列表、详情、联系页以及手机宽度，检查长标题、多语言、分页、空图片和表单反馈。
6. 根据客户反馈改模板、内容或风格卡，再 build。交付静态文件时运行 `export --out <工作空间外的新目录>`，得到 dist/ 与 manifest.json。不称为上线。

## 示例模式

只有用户明确希望先看示例时使用。内容标 sample=true，虚构企业字段记入 site.json 的 sample_fields，示例图片放 images/sample/。运行 `build --demo`，页面会显示示例标记；导出命令拒绝这种构建。真实内容替换后去除对应示例标记，再普通 build。隐藏内容不生成页面，但 images/ 会作为公开资源目录整体复制；不要把未采用的私密图片放进去。

## 表单与真实发布

本地内置片段固定展示姓名、电话、邮箱、国家；必填设置目前只是演示默认值。浏览器验证通过后显示“未发送、未保存”，不请求服务、不存询盘。实际表单版本、校验与提交规则待平台接入。导出包的 platform_ready=false，不宣称已经完成平台验收。

本地地址仅在运行工具的电脑打开，不能当作客户手机可访问的公网链接。需要外部预览时说明平台尚未接入，并按用户明确要求选择后续方式，不擅自部署。
